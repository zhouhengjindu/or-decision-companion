# UX References

## 体验原则来源

- **数字手账**：借鉴 Apple Journal 与 Day One 的时间感、留白和照片融入方式，让历史决定像个人生活证据，而不是后台记录。
- **一次一个问题**：借鉴引导式日记，把 Think Or 限制为每屏一个高信息量问题，避免表单审讯感。
- **即时收敛**：借鉴轮盘类工具的明确结果和短仪式，但移除赌场式动效和随机噱头。
- **氛围陪伴**：借鉴 Endel 的目的导向音景，用 Web Audio 生成 Focus / Dream / Night，不依赖版权素材。
- **精致反馈**：借鉴 Arc / Linear 的微动效纪律：动效只用于空间关系、状态变化和确认，不用作装饰性延迟。

## 页面体验基线

### Home

一个主要问题、一组 A/B 输入、三个模式选择、语音与照片入口。首屏不展示功能介绍、统计图或新手教程。

### Decision Flow

Fast Or 直接进入仪式；Think Or 最多 2 个问题；Deep Or 最多 4 个问题并使用可折叠的准则权重。始终显示可返回编辑的上下文。

### Result

先展示一个强结论，再给一行原因与置信度。`I'll do it` 是主操作，`Not this time` 是同等合法的用户覆盖；“Why?” 展开证据而非生成文章。

### Diary

按日期分组的卡片网格，允许图片、不规则轻微旋转和纸张层次，但保证文字可读、键盘可访问。空状态直接引导做第一个决定。

### Insights

只展示至少有真实样本支持的描述；样本不足时说明还需要几次决定，而不是填充假数字。

## 动效规范

- 仪式总时长 1.2–1.8 秒，尊重 `prefers-reduced-motion`。
- 页面进入 240–420ms；按钮反馈 120–180ms；不要用循环注意力动画。
- 结果以“收拢”而非“爆炸”出现，表达 quiet confidence。

## 无障碍与降级

- 所有图标入口有文字或 `aria-label`；键盘 focus 清晰。
- 语音不支持时在原位置显示文本 fallback，不弹阻塞对话框。
- 音频默认关闭且必须由用户手势开启；刷新后保留偏好。
- 图片上传预览支持移除，视觉描述字段始终可编辑。
- 色彩不是状态的唯一编码；结果、满意度和模式都有文字标签。
